# 台灣智慧局專利接入

## 兩條資料路徑

每週發現新核准案使用智慧局網路公報的公開 JSON 介面：先取得卷期與公告日，再讀取該期「審定公告目錄」的發明、新型及設計書目。這條路徑不需帳密，能保存該期完整清單；公報頁面的 PDF 只保存官方連結。

使用者核發的專利公開資訊 API 帳密用於已知申請號的補全。程式以 HTTP Basic Auth 取得 Bearer token，再呼叫：

- `getCaseInfo/{caseId}`：案件、分類、申請人與優先權。
- `getReationCase/{caseNo}`：關聯案件。端點拼字依官方手冊保留。
- `getResultFileList/{caseNo}`：程序文件歷程。首版只保留文件名稱、日期、類別與編號，不下載整批附件。

這套個案 API 沒有搜尋或列出最新核准案的端點。專案不會把帳密誤當成開放資料 API 的 `tk` 驗證碼；後者需要另一份申請。完整公報 FTP/FTPS 批次包含大型圖片與說明書，一期可能達數 GB，因此 MVP 先用公開公報 JSON 完整列舉書目，再只補全相關候選。

## 每週流程

1. 讀取官方近期期別，按 `as_of` 截止日及重疊窗口選取新期別。
2. 逐期讀完整書目並核對 `totalCount`、分頁與每頁筆數。
3. 將所有書目寫入本機 `data/patent-feeds/tipo-grants.json`，供跨週去重及網頁專利清單使用。
4. 依技術關鍵字與精確申請人別名產生候選；先處理公司直接命中、多主題與發明專利。
5. 在 `tipo_details_per_run` 預算內用個案 API 補充分類、優先權、關聯案及程序歷程，再交給 Codex 分段理解。
6. 網頁公開證書號、公告日、標題、申請人、官方 PDF 與詳細資料狀態；token、帳密、附件 URL 及本機原始資料不公開。

## 安全與判讀界線

帳密只從被 Git 忽略的 `.env` 讀取，只傳到固定的 `https://tiponet.tipo.gov.tw/S092_API/opd1/`。認證 token 只留在記憶體，不封存認證回應。下載連結必須是 `https://cloud.tipo.gov.tw`，不同主機會中止。

「核准公告」只證明該公報事件，不能推論目前仍有效、剩餘年限、權利未移轉或產品已商業化。公司映射只接受 watchlist 中的精確正式名稱／別名，並標為候選，後續仍需人工覆核。
