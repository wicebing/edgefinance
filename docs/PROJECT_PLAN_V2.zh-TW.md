# EdgeFinance 專案規劃 v2

## 目標

EdgeFinance 的工作不是從大量新聞直接產生「買進名單」，而是持續建立可驗證的前瞻研究紀錄：哪些技術正在解決高價值問題、成熟速度是否加快、哪些上市公司可能取得價值、財務與供應鏈是否開始證實，以及市場價格是否已經反映。

最終判斷分成兩個時間尺度：

- **3～10 年**：技術成熟、產業形成與公司價值取得。
- **90／180 天**：景氣、流動性、政策、匯率、供應鏈與事件風險。

網站呈現的是研究候選與查證狀態，不承諾報酬，也不把技術前景直接等同股票報酬。

## 淘金流程

### 1. 選擇可能含金的區域

資料來源依訊號用途分層，而不是無限制抓取網頁：

| 層次 | 目前來源 | 要回答的問題 |
|---|---|---|
| 發明活動 | USPTO、EPO、TIPO | 技術問題、申請人、成熟路徑是否出現結構變化？ |
| 公司營運 | SEC、MOPS 月營收、重大訊息 | 技術是否開始形成營收、資本支出或財務壓力？ |
| 市場與景氣 | World Bank、BLS、Treasury、FRED／ALFRED、ECB、TWSE、TPEx | 成長、通膨、利率、匯率及風險偏好處於什麼環境？ |
| 政策與事件 | 各國官方 RSS／公告、可信新聞 | 哪個事件可能改變需求、成本、供應或資本流動？ |
| 實物流量 | 港口、海關、Comtrade、船舶資料（下一階段） | 訂單與貨物流是否先於財報改變？ |

每個來源都必須記錄公開日期、首次取得時間、資料版本、涵蓋範圍、遺漏與授權。沒有取得的資料維持空缺，不補成零。

### 2. 保存沙子，但不把沙子全部公開

本機保存 gzip 原始回應、SHA-256、正規化文件、SQLite 索引、Codex 結果與處理游標。GitHub 只保存精簡報告、來源連結、公開指標及完整性 manifest。這可避免 Git repository 膨脹，也不會把帳密、MongoDB URI、模型 log 或可能受授權限制的全文發布出去。

MongoDB 保持選配。單機每週批次以 SQLite 加內容定址檔案最容易備份、回復與稽核；GitHub Pages 直接讀靜態 JSON，不需要瀏覽器連資料庫。

### 3. 把沙子淘成結構化訊號

原始文件先轉為共同欄位，再計算可重複的訊號。下一階段的主要特徵如下：

- 專利：家族去重、優先權日、IPC／CPC、引用速度、權利項範圍、共同申請人、發明人網路、地理擴張、撤回與法律狀態。
- 技術：主題增速、跨產業擴散、重要瓶頸、單位成本、可靠度、量產與法規門檻。
- 公司：月營收加速度、毛利與現金流、研發／資本支出、重大訊息、產品或客戶集中度。
- 景氣：成長、通膨、失業、利率曲線、信用利差、匯率、製造與外貿方向。
- 物流：港口吞吐、航線、品項、出口人／進口人與公司對應；所有對應保留可信度與證據。

### 4. Codex 淘洗

Codex 逐段抽取可引用主張，再做跨來源綜合。每個長期候選至少回答：

1. 技術解決什麼昂貴問題？
2. 目前成熟度與尚未解決的門檻是什麼？
3. 為什麼可能在 3～10 年內加速？
4. 哪家公司擁有可驗證的專利、產品、客戶、製造或通路位置？
5. 公司如何取得價值，競爭者或替代方案如何破壞它？
6. 財務資料是否支持，估值是否留下合理空間？
7. 哪個觀測會推翻論點？下一次何時檢查？

只有同時具備不同來源類型、公司營運證據及可否證條件的候選，才可由探索線索提升為跨來源研究候選。模型不得用資料筆數當成技術重要性，也不得自行補造市場規模或機率。

### 5. 顯示黃金與雜質

首頁顯示最新週報、長期候選、90／180 天風險及進度。全球頁比較主要經濟體，台灣頁顯示最近交易日、市場廣度、月營收與重大訊息。每個結論連回來源；資料不足、金鑰缺少、抽樣、處理上限與模型待讀分段都要可見。

## 每週作業

1. 執行 `scripts/weekly.ps1`，抓取新資料並接續未完成佇列。
2. Codex 只處理尚未完成的內容分段，沿用通過驗證的結果。
3. 生成凍結週報與 JSON manifest；執行測試、完整性及秘密掃描。
4. 人工檢查高影響結論、公司對應、日期、單位與引用。
5. 提交 `public-data/` 與程式變更；GitHub Actions 從凍結資料建站。
6. 到期後記錄先前 90／180 天條件是否發生，不回頭改寫原報告。

## 如何知道方法真的有用

沒有樣本外紀錄前，不宣稱選股勝率。每個新候選保存首次出現日、當時可用證據、預期驗證條件及期限。後續加入調整股利與拆股的價格資料後，與相同地區／產業基準比較 3、6、12、36 個月總報酬，並分開衡量：

- 方向正確率與相對報酬。
- 最大回撤及訊號後等待時間。
- 有無專利、營運、物流等資料時的增量效果。
- 不同資料品質與模型版本的穩定性。
- 候選被撤銷、失效或未通過估值門檻的比例。

評估程式必須使用當週凍結資料，避免前視偏誤、存活者偏誤與使用後來修訂的總經數值。

## 演化順序

1. 完成全球與台灣官方資料的穩定週更、告警與資料品質測試。
2. 專利家族、分類、引用與法律狀態圖譜；以完整批次取代樣本頁。
3. 加入公司行情、估值與公司行動，建立可比較的時點快照。
4. 接入 UN Comtrade、港口吞吐與可合法使用的物流資料，建立品項—公司對應。
5. 建立前瞻評估與基準，據結果調整訊號權重。
6. 只有在資料品質與樣本外結果支持後，才提供明確排序；仍保留不確定性與人工覆核。
